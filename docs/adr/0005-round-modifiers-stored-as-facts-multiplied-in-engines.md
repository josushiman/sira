# Round modifiers are stored as facts and multiplied only in the Engines

Çifte and Okey atmak both scale a Round's scoring, but their rules differ per Entrant (Çifte doubles asymmetrically depending on whether a caller won; Okey atmak doubles everyone uniformly), and they stack, so a single Entrant can end a Round at ×4. We decided that `Round` records only *who did what* — `cifteCallers: Set<Entrant.ID>` and `okeyAtanID: Entrant.ID?` — with `Round.deltas` holding the **raw** entered counts, and every multiplier derived in the Engines, which are the single place any doubling is applied. Alternatives considered: storing a precomputed `multipliers: [Entrant.ID: Int]` (rejected — bakes today's reading of the rules into saved data and leaves the scoresheet unable to say *why* an Entrant doubled), and keeping the current arrangement where the entry screen pre-multiplies (rejected — that is exactly what produced the ×4 Çifte bug in Okey 101, where `RoundEntryState.deltas` doubled and `FixedRoundsEngine` then doubled the same Round again). Consequence: `RoundEntryState`'s doubling is presentation-only — it feeds the on-screen preview and must never be what `onSave` hands to the store — and any new modifier gets added as a fact on `Round` plus multiplier logic in each Engine, never as arithmetic in a view.
